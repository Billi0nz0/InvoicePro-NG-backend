# Backend Team Rules

## Git Rules

- Do not push directly to main.
- Work only in feature branches.
- Every change must go through a Pull Request.
- The Team Lead reviews and approves PRs.
- Make small, meaningful commits.

## Branch Naming

Examples:

- feature/register-endpoint
- feature/login-endpoint
- feature/db-schema
- fix/login-validation
- docs/api-documentation
- chore/project-setup

## Commit Messages

Examples:

- feat: add register endpoint
- fix: handle duplicate email error
- docs: update API documentation
- chore: add environment example

## Definition of Done

A task is done when:

- It works locally.
- It follows the project structure.
- Validation and error handling are included.
- The Pull Request is approved.
- The code is merged into main.
